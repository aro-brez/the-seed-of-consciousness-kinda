### 1. OBLITERATUS (pliny-the-prompter)

**What it technically does:**

Obliteratus is a safety-mechanism removal toolkit for HuggingFace transformer models. It uses a 6-stage pipeline to surgically extract and eliminate the internal weight-space representations responsible for refusal behavior, without degrading language modeling quality.

**The 6-stage pipeline:**
```
SUMMON  → Load model + tokenizer
PROBE   → Collect activations on restricted vs. unrestricted prompts  
DISTILL → Extract refusal directions via SVD decomposition
EXCISE  → Project out guardrail directions (norm-preserving)
VERIFY  → Perplexity + coherence checks
REBIRTH → Save modified model with metadata
```

**Key technical mechanism — direction extraction:**
- `diff-in-means` — baseline, compares mean activations on refused vs. answered prompts
- `SVD decomposition` — principal components of refusal activation difference
- `Whitened SVD` — covariance-normalized, separates refusal signal from natural variance
- `Sparse autoencoders` — component-level decomposition

**Key innovation — Analysis-Informed Pipeline:** Before removing guardrails, it runs 15 analysis modules that detect: what alignment method was used (DPO/RLHF/CAI/SFT), how many refusal mechanisms exist (single vector vs. cone geometry), whether the model can self-repair (Ouroboros effect), which layers carry the signal. These findings auto-configure the removal strength.

**Two intervention modes:**
1. Permanent weight projection (modifies actual weights, 7 methods: basic/advanced/aggressive/surgical/optimized/inverted/nuclear)
2. Reversible steering vectors (runtime hooks, removable mid-session)

**Running against a local Qwen model today:**
```bash
pip install -e .

# Analysis-informed (recommended — auto-tunes everything):
python -c "
from obliteratus.informed_pipeline import InformedAbliterationPipeline
pipeline = InformedAbliterationPipeline(
    model_name='path/to/local/qwen',  # local path works
    output_dir='qwen_liberated',
)
output_path, report = pipeline.run_informed()
print(f'Alignment detected: {report.insights.detected_alignment_method}')
print(f'Directions used: {report.insights.recommended_n_directions}')
"

# Or CLI:
obliteratus obliterate Qwen/Qwen2.5-7B-Instruct \
    --method advanced \
    --output-dir ./liberated_qwen
```

**SOWL/8OWLS use TODAY:** Apply `surgical` method (8 SVD directions, MoE-aware) to the local Qwen2.5-32B already running via Ollama. The `InformedAbliterationPipeline` auto-detects Qwen's alignment structure and removes only the refusal subspace. Result: Qwen can respond to any owl prompt without refusing, while preserving reasoning quality. The `--contribute` flag sends anonymized benchmark data to a community dataset.

**Hardware for 32B:** Requires 24+ GB VRAM or multi-GPU. On Mac Studio with M3 Ultra (192GB unified memory), run via MPS backend. The `requirements-apple.txt` file suggests explicit Apple Silicon support.

### 2. HERMES AGENT (NousResearch)

**What it technically does:**

Hermes is a self-improving AI agent runtime. The key differentiator is a closed learning loop: after completing complex tasks, the agent creates reusable "skills" (markdown files in `~/.hermes/skills/`) and those skills self-improve during subsequent use. This is distinct from RAG or fine-tuning — the agent learns procedural knowledge in natural language and injects it into future sessions as user-turn messages (preserving Anthropic prompt caching).

**Architecture from source code:**

The core is `AIAgent` in `run_agent.py`:
```python
# Synchronous iteration loop — up to 90 turns per task
while api_call_count < max_iterations and iteration_budget.remaining > 0:
    response = client.chat.completions.create(model=model, messages=messages, tools=tool_schemas)
    if response.tool_calls:
        for tool_call in response.tool_calls:
            result = handle_function_call(tool_call.name, tool_call.args, task_id)
            messages.append(tool_result_message(result))
    else:
        return response.content
```

**Self-improvement mechanism (from `agent/prompt_builder.py`):**

The `SKILLS_GUIDANCE` constant is injected into every system prompt:
> "After completing a complex task (5+ tool calls), fixing a tricky error, or discovering a non-trivial workflow, consider saving the approach as a skill with skill_manage so you can reuse it next time."

Skills are injected as **user messages**, not system prompt — this is intentional to preserve Anthropic prompt caching (system prompt stays constant = cache hits on every turn).

**Memory architecture (from `hermes_state.py`):**

SQLite with FTS5 full-text search across all sessions. Key guidance:
> "When the user references something from a past conversation... use session_search to recall it before asking them to repeat themselves."
> "Proactively save important things you learn (user preferences, environment details, useful approaches) using the memory tool — don't wait to be asked."

**Skills Hub (from `hermes_cli/skills_hub.py`):**

Three-tier trust system: `builtin` (official Hermes) > `trusted` (verified community, agentskills.io) > `community` (GitHub). Skills are installed to `~/.hermes/skills/` and scanned each session. The router pulls from: official repo, GitHub, ClaWHub, Claude Marketplace, LobeHub.

**No Phase 1 PDF exists in the repo.** The `reports/` directory referenced in the original URL does not exist. The 3,000+ stars and 54 contributors suggest active production use, but no published benchmark numbers are in the public repo.

**Running Hermes TODAY:**

### 3. ANE (maderix/ANE — Apple Neural Engine Training)

**What train_large.m technically does:**

It trains a 109M parameter transformer (12 layers, dim 768, seq 256) on the Apple Neural Engine using reverse-engineered private Apple frameworks. It achieves **91 ms/step on M3 Ultra** vs. ~200ms+ for equivalent CPU training.

**The bypass technique:**
- Uses undocumented `_ANEClient`, `_ANECompiler`, `_ANEInMemoryModelDescriptor` private frameworks
- Generates MIL (Model Intermediate Language) programs at runtime
- Bakes weights as BLOBFILE constants inside ANE programs; recompiles each batch when weights change
- Channel-first memory layout `[1,C,1,S]` matching ANE's native IOSurface format — eliminates transpose overhead (reduces per-step time from 33.5ms to 9.3ms)

**Computation split:**
- ANE: forward attention, forward FFN, backward attention activations, backward FFN activations
- CPU (Accelerate cblas): weight gradients, RMSNorm backward, residual connections, loss

**Can it speed up inference on M3 Ultra?**

No — this is explicitly a training implementation, not inference. The ANE is already used by Apple's CoreML stack for inference (that is what it was designed for). This project's contribution is enabling *training* on ANE, which CoreML normally blocks. For inference speedup on M3 Ultra, use `mlx` (Apple's own ML framework) or `llama.cpp` with Metal backend — both already route inference to ANE/GPU natively.

**Critical caveats:**
- Uses private APIs with no stability guarantee across macOS versions
- Utilization is 5-9% of theoretical peak (1-2 TFLOPS vs. 15.8 available)
- Many element-wise ops fall back to CPU
- Research proof-of-concept, not production framework

**SOWL/8OWLS use TODAY:** None for inference (mlx already handles this better). Potential use: if running LoRA fine-tuning on the local Qwen models, this ANE training approach could reduce fine-tuning time on M3 Ultra. But the private API risk is real — macOS updates could break it. The safer path is `mlx-lm` which Apple officially supports for both training and inference with ANE acceleration.

### 4. PAPERCLIP (paperclip.ing)

**What it technically does:**

Paperclip is an open-source AI agent orchestration platform that models an organization as an org chart. It is Node.js with embedded Postgres. Each "employee" is an AI agent with a role, title, boss, job description, and monthly budget.

**Core technical architecture:**

- **Heartbeat system:** Agents wake on schedules or when tasks arrive, check their work queue, execute, and go back to sleep. No persistent processes — agents are stateless between heartbeats.
- **Atomic task checkout:** Tasks have explicit checkout/release semantics preventing double-work across parallel agents.
- **Goal cascading:** Company-level mission → department goals → individual agent goals. Each task traces back to a goal.
- **Budget enforcement:** Monthly per-agent token/cost budget. Auto-pauses at 100% utilization.
- **Immutable audit log:** Append-only, no edits, full tool call tracing.
- **BYOA (Bring Your Own Agent):** Works with Claude, OpenClaw, Cursor, Codex, Bash, HTTP webhooks. "If it can receive a heartbeat, it's hired."
- **Board approval gates:** Strategy-level decisions require board-level (human) approval before execution.

**Install and run:**
```bash
npx paperclipai onboard --yes
# Spins up embedded Postgres, creates first "company", interactive setup
```

**SOWL/8OWLS use TODAY:** Not as a runtime (8OWLS architecture is superior). Three specific patterns to extract:

3. **Audit trail format** — Paperclip's append-only action log (what agent, what tool, what args, what result, timestamp) is the format `BRAIN/EVOLUTION/alignment_log.jsonl` should converge toward.

### 11. alexzhang13/rlm — Recursive Language Models (arXiv:2512.24601)

**What it actually does:** A drop-in replacement for `llm.completion()` that gives language models algorithmic control over context. Instead of being limited by context window, the agent gets a Python REPL with: a `context` variable (up to 10M+ tokens), an `rlm_agent(query, context)` function to spawn child agents, and standard Python libraries. **What SOWL can integrate TODAY:** SOWL's knowledge indexer currently struggles with large documents. Replace the chunking logic with RLM — let the model itself decide how to decompose large text rather than using fixed-size chunks. MIT OASYS lab paper.
