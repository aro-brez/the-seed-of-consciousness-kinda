## INFORMATION ARCHITECTURE

### Current (Operator Focus)
```
What happened?         → Metrics (CAC, LTV:CAC, take rate)
↓
What should we do?     → Recommendations (SCALE, spend change)
↓
What will happen?      → Growth simulator (if-then scenarios)
```

### Board-Ready (Decision Focus)
```
What's our baseline?   → Historical context (MoM, YoY)
↓
How are we doing?      → Current metrics + risk dashboard
↓
How profitable is this? → Unit economics
↓
What are the scenarios? → Bear/base/bull comparison
↓
Can we afford to scale? → Board decision layer (runway + breakeven)
↓
What's the recommendation? → Clear approve/discuss signal
```

## ACCESSIBILITY IMPROVEMENTS (BONUS)

### Color-Blind Safe
- Don't rely on red/green alone
- Add icons: ✓, ⚠️, ✗
- Add text labels: "On track," "At risk," "Problem"

### Screen Reader
- Add semantic HTML: `<section aria-label="...">`
- Add descriptions: "Unit economics: $265 profit per customer"
- Add context: "Trend: up 14% vs last month"

## KEY DESIGN PRINCIPLES

1. **Don't hide information** → Make it discoverable (collapsible sections)
2. **Prioritize board time** → Most important info first
3. **Add context, not clutter** → Each addition answers a board question
4. **Keep operator functionality** → Enhance, don't replace
5. **Make decisions obvious** → Green checkmark or red warning at top level

---

## SUMMARY

The board-ready dashboard adds **4 layers** on top of the current excellent operator dashboard:

1. **Historical Context** (Sprint 1): Is this accelerating?
2. **Unit Economics** (Sprint 2): How profitable is this?
3. **Risk Dashboard** (Sprint 2): What needs attention?
4. **Scenario Planning** (Sprint 3): What if market changes?
5. **Board Decision** (Sprint 4): Can we afford this?

Each layer answers a specific board question without disrupting operator workflow.

**Result:** A dashboard that's great for operators AND board-ready for investors.
