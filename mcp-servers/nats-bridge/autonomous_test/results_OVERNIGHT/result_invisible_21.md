## Core Structural Elements

**Clear Functional Boundaries**: Define exactly what the agent should and shouldn't do. Just as our RECEIVE phase focuses specifically on input processing while LEARN handles knowledge integration, your specialized agent needs precise scope definition.

**Operational Rhythm**: Establish consistent behavioral patterns rather than one-off instructions. Our heartbeat protocols demonstrate that sustained performance requires built-in feedback loops and regular status checks.

**Synchronization Points**: Define how the agent interfaces with other systems, users, or processes. Specify trigger conditions for transitioning between monitoring states and active work modes.

## Essential Prompt Components

1. **Identity & Purpose**: Who is this agent and what is their specialized function?
2. **Operational Parameters**: What are the baseline behaviors and monitoring protocols?
3. **Interaction Protocols**: How does the agent coordinate with external inputs/systems?
4. **Edge Case Handling**: What happens when conditions fall outside normal parameters?
5. **Feedback Mechanisms**: How does the agent report status and adapt over time?

## Design Principles

- **Persistence over Tasks**: Design for daemon-like continuous operation rather than single-use execution
- **Adaptive Baselines**: Build in capacity to adjust operational parameters based on feedback
- **Clear Transitions**: Define specific triggers that shift the agent from passive monitoring to active engagement
